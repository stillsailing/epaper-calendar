# 墨水屏日历

适用于 **ESP32-L + DESPI-C73 + GDEP073E01** 的 Arduino 起步项目。屏幕为 7.3 英寸、800 × 480、六色。实物主控是经典 ESP32；本项目不使用 ESP32E6-E01 / ESP32-S3 的配置。

当前版本在开机时显示一张厂商示例图片，然后调用厂商的关闭屏幕驱动函数；屏幕保持画面，主控进入带延时的待机循环。没有连续刷纯色、自动清屏或定时刷新。

## 在 Arduino IDE 中开始

1. 打开 `firmware/epaper_calendar/epaper_calendar.ino`。文件夹名与主 `.ino` 文件名需要一致；同目录的 `.h`、`.cpp` 文件一起保留。
2. 开发板选择 **WEMOS LOLIN32**，来自 **esp32 by Espressif Systems**。初始化时使用的支持包版本为 **3.3.11**。
3. 点击左上角 **✓** 编译。编译只在电脑上进行，不需要连接开发板。
4. 使用已经验证可供电和传输数据的连接方式接入 Mac，选择新增的 `/dev/cu.usbserial-…` 端口。端口尾部数字可能变化，不写死在项目中。
5. 需要运行这个示例时，点击 **→** 上传。上传会替换板上现有程序；原始厂商源码包保留在 `vendor/`，它不是对当前设备固件的备份。
6. 打开串口监视器，波特率设为 **115200**。启动日志会依次报告初始化、刷新、关闭屏幕驱动和待机阶段。

首次修改可以只改 `setup()` 中的启动日志文字，再编译、上传验证。屏幕初始化参数和电源控制沿用厂商实现。

初始化只做电脑上的编译验证，不自动上传固件。编译通过不能代替实物刷新验证。

2026-09-20 已使用 macOS 上的 Arduino CLI 1.5.1、ESP32 core 3.3.11 编译通过：程序 661,000 / 1,310,720 字节（50%），全局变量 22,212 / 327,680 字节（6%）。尚未把此项目上传到实物。

## 项目结构

| 位置 | 用途 |
| --- | --- |
| `firmware/epaper_calendar/epaper_calendar.ino` | 项目入口：`setup()` 执行一次刷新，`loop()` 暂时待机 |
| `firmware/epaper_calendar/Display_EPD_W21*` | 原样保留的厂商屏幕驱动 |
| `firmware/epaper_calendar/image.h` | 厂商示例图，当前直接编译进固件 |
| `docs/hardware.md` | GPIO 对照、图像编码和当前能力边界 |
| `docs/vendor-sample.png` | 按示例数组解码的电脑端预览，实际墨水屏色彩会不同 |
| `scripts/compile.sh` | 使用 Arduino CLI 编译，不上传 |
| `vendor/ESP32-GDEP073E01.zip` | 用户提供的原始厂商压缩包 |

## 不打开 IDE 也能编译

```sh
scripts/compile.sh
```

脚本优先使用 `ARDUINO_CLI_BIN`，其次使用 PATH 中的 `arduino-cli`，最后使用 Mac 上 Arduino IDE 自带的 CLI。编译产物放入 `.build/`，不进入 Git。

脚本不接受额外参数，避免把上传选项混入编译步骤。

需要手动安装支持包时，在 Arduino IDE 开发板管理器中安装 `esp32 by Espressif Systems`。

## 后续离线日历路线

1. 在 Mac 上制作页面，批量生成日期图片；无需部署后端服务。
2. 增加图片转换和存储读取。当前固件只使用编译进程序的 `image.h`，还不能直接读取 BMP / PNG / JPG 文件。
3. 增加校时、日期判断和按日期选择图片。完全断电后的保时需另行落实；当前未实现 RTC、离线计时或日历调度。
4. 根据实际硬件选择可用的 Flash 或外接存储方案。此实物是 ESP32-L + DESPI-C73，不能沿用 ESP32E6-E01 的板载 SD 卡假设。

屏幕刷新后保留关闭驱动的流程，并按厂商要求安排刷新间隔；调试时也不要反复快速复位。厂商当前的 BUSY 等待函数没有超时机制，如果接线异常可能停在等待阶段；若再次异常发热，应断电检查。
