# 硬件与编码

## 已确认的组合

- 主板：Good Display ESP32-L，ESP32-WROOM-32D 模块。
- 转接板：DESPI-C73。
- 屏幕：GDEP073E01，800 × 480，黑、白、黄、红、蓝、绿六色。外形 170.2 × 111.2 × 0.91 mm（实测），外壳见 `docs/enclosure.md`。
- Arduino 板型：WEMOS LOLIN32。
- FQBN：`esp32:esp32:lolin32`。
- 当前验证的 Arduino ESP32 支持包：3.3.11。

以用户实物、提供的压缩包以及当前支持包的 `variants/lolin32/pins_arduino.h` 为依据。以下为 GPIO 编号，不是模块的物理引脚序号。

| 信号 | 厂商别名 | GPIO |
| --- | --- | --- |
| BUSY | A14 | 13 |
| RESET | A15 | 12 |
| DC | A16 | 14 |
| CS | A17 | 27 |
| SCK | SCK | 18 |
| MOSI / SDI | MOSI | 23 |

注意：原始 `Display_EPD_W21_spi.h` 里关于 SCK / SDIN 的两行注释与 LOLIN32 的实际默认值相反。原始文件保留原样；项目入口明确使用 SCK=18、MOSI=23，并对 A14-A17 的值做编译期检查。

SPI 保留厂商的 10 MHz、MSB first、Mode 0 设置，先执行 `SPI.begin()`，再执行 `SPI.beginTransaction()`。板载字库和额外 Flash 暂未使用。

## 当前图片格式

`image.h` 中的 `gImage_1` 是 **384,000 字节**的 C 数组，即 800 × 480，每像素 1 字节。它不是 BMP 文件，也不是 PNG / JPG 文件。

| 颜色 | 数组中的字节值 | 发送给屏幕的半字节值 |
| --- | --- | --- |
| 黑 | `0x00` | `0x0` |
| 白 | `0xFF` | `0x1` |
| 黄 | `0xFC` | `0x2` |
| 红 | `0xE0` | `0x3` |
| 蓝 | `0x03` | `0x5` |
| 绿 | `0x1C` | `0x6` |

厂商 `PIC_display()` 逐行读取数组，经 `Color_get()` 转换后，将两个像素打包为一个字节发送。以后生成自己的图片时，需要输出上述六色编码，或者另外实现图片文件解码；不能直接把 BMP 文件字节放进这个数组。`scripts/convert_image.py` 会按这个编码输出数组；`Color_get()` 会把表外的字节当作黑色，脚本输出不会包含表外字节。

## DS3231 时钟模块

| DS3231 | ESP32 | 说明 |
| --- | --- | --- |
| VCC | 3.3V | 不要接 5V，避免 I²C 上拉到 5V |
| GND | GND | |
| SDA | GPIO21 | 修改 `kRtcSdaPin` 可以换引脚 |
| SCL | GPIO22 | 修改 `kRtcSclPin` 可以换引脚 |

GPIO21/22 是 LOLIN32 的默认 I²C 引脚，**尚未确认 ESP32-L 排针是否引出、是否空闲**。如果需要换引脚，避开以下几类：
- 屏幕已经占用的引脚（12、13、14、18、23、27）；
- 启动配置引脚（0、2、5、12、15）；
- 只能输入的引脚（34–39）；
- 接 Flash 的引脚（6–11）。

常见的 ZS-042 型 DS3231 模块要注意两点：
- 板上带一个给纽扣电池充电的电路，按设计适配可充电的 LIR2032。装不可充电的 CR2032 时，通常要拆掉充电电阻或二极管。
- 板上的电源指示灯会持续耗电，电池供电时建议拆掉。

购买后请对照实际模块的资料确认。

没有接 DS3231 时，固件改用内部时钟模式：芯片保持唤醒、不进深度睡眠，必须一直接 USB 电源，详见 README。

DS3231 保存的是本地时间，不处理时区和夏令时。状态寄存器的振荡器停止标志（OSF）置位时，固件认为时间不可信，会显示 fallback 页面，直到重新校时。

## 按键

7 个按键，按外壳上从左到右的顺序（从正面看）：

| 位置 | 按键 | ESP32 | 作用 |
| --- | --- | --- | --- |
| 1 | 激活 | GPIO32 | 把芯片从深度睡眠中唤醒，醒着时按下没有作用 |
| 2 | 上一月 | GPIO33 | 往前翻一个月，日期按月底截断（3 月 31 日 → 2 月 28/29 日） |
| 3 | 上一天 | GPIO25 | 往前翻一天 |
| 4 | 今天 | GPIO26 | 回到今天，并强制重刷 |
| 5 | 下一天 | GPIO4 | 往后翻一天 |
| 6 | 下一月 | GPIO16 | 往后翻一个月 |
| 7 | 月历 | GPIO17 | 在当天页和整月月历页之间切换，今天那一格显示成红底白字 |
| 模块 V | 3.3V | | 给模块的上拉电阻供电，**不要接 5V** |
| 模块 G | GND | | |

- **电平：** 按键按低电平有效，按下时引脚接到 GND。固件开了内部上拉，模块自带上拉也可以。如果模块按下时输出高电平，需要修改固件。
- **引脚选择：**
  - 这 7 个引脚都有内部上拉，也都不是启动配置引脚。
  - GPIO16/17 在 ESP32-WROOM-32D 上是空闲的；如果模块换成带 PSRAM 的 WROVER，就不能用这两个引脚。
  - 修改 `kWakePin` 等常量可以换引脚，但激活键必须用 RTC GPIO（0、2、4、12–15、25–27、32–39），否则不能唤醒。
- **唤醒：** DS3231 模式下只有激活键能唤醒（ext0）。经典 ESP32 能按低电平唤醒的源只有两路，每路只能接一个引脚。所以用一个专门的激活键，不用二极管把所有按键并到一起。
  - 按一下激活键，30 秒内其他键都能用；
  - 30 秒没有操作就继续睡；
  - 内部时钟模式下芯片一直醒着，所有键随时都能用。
- **卡键保护：** 睡眠前如果激活键正被按住（或者卡住），这一次不把它设为唤醒源，避免芯片反复被唤醒、耗光电池。

## Flash 分区与页面数据

`firmware/epaper_calendar/partitions.csv` 按 4 MB Flash 划分：

| 分区 | 偏移 | 大小 | 内容 |
| --- | --- | --- | --- |
| nvs | 0x9000 | 20 KB | 系统保留 |
| otadata | 0xE000 | 8 KB | 上传时写入 `boot_app0.bin` |
| app0 | 0x10000 | 1.25 MB | 固件，与 lolin32 编译时的大小上限 1,310,720 字节一致 |
| calendar | 0x150000 | 2.75 MB | `pack_calendar.py` 的输出，由 `flash_data.sh` 写入 |

页面数据格式写在 `scripts/pack_calendar.py` 文件开头的说明里，概括如下：
- 文件头 16 字节，之后是按日期排序的索引；
- 每页是一段 zlib 数据流，解压后得到 192,000 字节，每字节两个像素，高 4 位是左边的像素，取值就是上表中“发送给屏幕的半字节值”；
- 每页都带有压缩数据的 CRC-32。

固件使用 ESP32 ROM 中的 `tinfl_decompress`（miniz）流式解压，每次从 Flash 读取 4 KB，解压期间临时占用约 47 KB 堆内存（字典 32 KB、解压状态约 11 KB、读缓冲 4 KB）。

## 启动流程

`串口初始化 → 看门狗 → 读 DS3231（冷启动时等待 5 秒校时命令）→ 日期变化时：查找页面并校验 → GPIO / SPI 初始化 → EPD_init → 发送 0x10 和页面数据 → 0x12 刷新 → EPD_sleep → 深度睡眠`

内部时钟模式下最后一步不进深度睡眠，而是进入 `loop()`：每 200 ms 喂一次看门狗、读取串口命令、检查日期，跨过零点时刷新。

刷新时序与厂商 `PIC_display()` 相同，只是数据来源从 `image.h` 改成了 Flash 中的压缩页面。使用普通全刷初始化。`EPD_sleep()` 在当前厂商代码中只发送电源关闭命令，深睡眠命令被厂商注释掉了，所以这里称为“关闭屏幕驱动”，不声称屏幕已经进入深睡眠。主控本身会进入 ESP32 深度睡眠。

## 使用边界

已实现：
- 按日期显示预先生成的页面；
- DS3231 计时和串口校时；
- 没有 DS3231 时的内部时钟模式（必须一直接 USB 电源）；
- 每日定时唤醒；
- 看门狗限制刷新卡死的时间。

未实现：
- Wi-Fi；
- 文件系统和 SD 卡；
- 电池电量检测；
- 屏幕深睡眠命令；
- 法定节假日和调休（页面已有农历、节气和传统节日，由 Mac 端生成）。

**以上都还没有在实物上验证。**

在已经确认正确的接线基础上开发；更改排线、转接板或跳帽前先断电。固件构建不验证物理接触和电源状况。
